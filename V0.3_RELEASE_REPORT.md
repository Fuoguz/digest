## Product hypothesis / What changed

An observed misunderstanding should lead to a different-context independent attempt, not disappear when the student clicks “revision complete.” The new loop keeps first answer → feedback → source evidence → revision → changed text → targeted new challenge → second answer → outcome → returnable history.

The existing warm editorial UI, task-first Dashboard, course import, chunk/resume Reader, quoteId engine, bilingual interface, independent feedback language, Review and Graph remain. There is no framework or product-wide visual rewrite.

## LearningGap model

Two stores are added: `learningGaps` and `retests`. A gap has provenance to Course, Task, original Attempt, Feedback and feedback item; exact answer excerpt (or a genuine omission), material anchors, kind, description/action, timestamps, dismissal/defer flags and retest history. Default maximum: three substantive observations. Forged excerpts, internal field names and style-only advice are excluded. Non-omission observations require an actual answer excerpt.

States: `observed`, `retesting`, `resolved_once`, `still_present`, `inconclusive`. Dismissal is separate, preserving history. Weak or absent material support remains inconclusive. No score or mastery percentage exists.

## Feedback prioritization

The model is asked to read the whole answer, accept reasonable alternatives and return **zero to three** important issues. Real QA exposed nitpicking caused by requiring at least one issue; the refined prompt accepted both reasonable and corrected answers with zero gaps. An omission contradicting praise of the same exact excerpt does not become a permanent gap. Deterministic normalization/bigram comparison merges near-duplicate explanations and matching issue/action pairs, unions evidence, and ranks substantive, excerpt-grounded observations first. Only the first three issue cards are expanded. Extra cards are collapsible. This is a heuristic, not a semantic proof that two issues are identical.

## Revision Diff

Original Attempt is immutable; revisions append. A small inline diff shows removed and added text relative to the original. It uses common prefix/suffix to remain bounded on long Chinese/English answers, so the middle change span can include unchanged internal words. It does not infer that the revision is correct or claim which feedback was definitely resolved. Zero-gap feedback can finish while retaining the original answer without manufacturing a revision. The persisted `completedWithoutRevision` flag is accepted only with zero-gap feedback and no revision; this completion is explicitly not an activation candidate.

## Next Challenge

Challenge reuses Task with `targetGapId` and structured generation metadata: prompt, hypothetical scenario, material scope, type, difficulty, hidden rationale and old/new context. The prompt includes original task/answer, latest revision, target observation and relevant material. It requests transfer, not a paraphrase or answer hints. Schema, scope and obvious repetition are rejected before persistence. Rationale is not rendered as a student answer hint.

One click after revision generates or resumes an unfinished challenge. “Later” makes it findable on Dashboard, Course and Review. Completed observations can be deliberately rechecked from history. Three optional material-based task suggestions prefill an editable form; nothing is auto-created.

## Retest semantics

The second answer is saved before AI. Evaluation is targeted to the same gap and returns a reason, exact answer excerpt, source anchors and one next action. Short answers, unsupported evidence, invalid excerpts, inadequate tasks/materials force `inconclusive`. `resolved_once` means this demonstration only. Model judgments remain fallible.

Atomic writes check request IDs, task IDs/version, original answer, current gap state, source signatures and cancellation. Dismissal, stale responses or changed material cannot overwrite newer learning state. Failure preserves both answers and revision; retry evaluates the saved second Attempt.

## Retrieval Rescue

Existing bounded lexical retrieval remains. Cross-language/low-overlap partial contexts may request up to eight source-language terms once. The prompt explicitly specifies the detected Chinese/English material language: the first live test otherwise returned Chinese terms for English source and safely fell back, missing the late relevant paragraph. Terms must occur in source, are never treated as facts, and do not rewrite it. Two 12k lexical selections merge/deduplicate; adoption requires increased term coverage. Failure or no improvement returns the original selection. Runtime diagnostics stay local to the opt-in test, not analytics. This is a recall heuristic, not semantic retrieval completeness.

## Data migration / Backup

IndexedDB `digest-v02` advances to version 3, creates two missing stores and never clears data. Challenge is an extension of existing Task; Retest has a compatibility Feedback record. Existing Graph, confirmed relations, Review and ReadingResult persist.

Backup keeps format `digest-v02`, version 3. v1/v2 backups restore with empty new stores. ## Competitive differentiation / Answers to release questions

1. **Added value:** a specific observed issue becomes a new independent practice and a persistent outcome, with source and revision history.
2. **Beyond a one-shot dialogue:** automatic provenance/state links, source-version-aware previews and returnable recheck queue. Content generation alone is not distinctive.
3. **Friction:** after the existing revision, one challenge action, one genuinely new answer and one submit; defer or dismiss each takes one action. This is deliberate practice, but generation latency adds waiting. No student-time benchmark is claimed.
4. **Gap usefulness:** it actually targets a new task and controls recheck/history state. Its pedagogical usefulness depends on observation/challenge quality; persistence alone is insufficient.
5. **Transfer:** the live night-market case changes the context and requires application; the bad repeat was rejected. This demonstrates near transfer only. Its explicit faulty claim makes it easier than an unprompted real case.
6. **Largest risk:** plausible but incorrect or over-specific model judgment becoming a persistent training target, compounded by unreliable model transport.
7. **Promote?** Not yet. Keep Production unchanged. A monitored Preview trial with five informed students is reasonable, but upstream reliability, latency and a course-informed human review of challenge quality should precede promotion.

## Next validation questions / Recommended experiment

With five students, use one real course task, then one revision and one different-context retest. Reopen after two–three days to try another case.
