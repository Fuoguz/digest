## 冻结与架构

稳定 Core 为 9cd331f，annotated tag `v0.2-core`。Pilot 不改变 IndexedDB stores 或 Reader/Evidence/Review/Graph 领域模型。

Browser → same-origin `/api/digest` 或 `/api/relations` → Vercel Node Function → 服务端固定的 OpenAI-compatible endpoint。`/api/access` 验证试用码，设置签名会话。公网默认 Proxy；本地 localhost 为 Developer 模式；开发者可在设置显式选择 Developer。

## Vercel 配置与发布边界

`vercel.json`：Framework Other/null，build `npm run build`，output `dist`，函数 maxDuration 180 秒。仅 `/app` 与 `/app/:path*` rewrite 到 `/app/index.html`；`/api/*` 不匹配 SPA 规则。其他未知静态路径由平台 404，App 内未知页面由应用显示未找到。

`dist` 只包含 Landing/App、客户端模块和 vendor；不再复制开发 server/package 文件。实际部署通过 `node scripts/prepare-pilot.mjs` 创建 `.pilot-deploy` 独立上传目录，只复制明确列出的产品源文件、build script、package manifests、api/pilot/vercel config。根目录 `.vercelignore` 的原始白名单被 CLI 识别不完整，首次部署因此失败；后续均从隔离目录部署。不要直接从根目录 deploy。不会上传 qa-artifacts、tests、mock server、用户文档、视频目录或 `.agents`。异常 `.gitignore/` 不动。

参考：Vercel 官方 [rewrites](https://vercel.com/docs/routing/rewrites)、[function duration](https://vercel.com/docs/functions/configuring-functions/duration)。

## Secrets 与 Access Gate

Dashboard → Project → Settings → Environment Variables，添加以下名称，值不写入本文、Git、截图或聊天：

| 名称 | 用途 |
|---|---|
| MODEL_API_KEY | 服务端模型 Key |
| MODEL_API_BASE_URL | HTTPS 模型 API 基地址（通常以 /v1 结尾，可含 /chat/completions）；不接受客户端地址 |
| MODEL_NAME | 服务端模型名称 |
| PILOT_ACCESS_CODE | 至少 16 字符、随机生成的高熵试用码，私下发给受邀学生 |

生产环境必填；若验收 Preview 也要在那里配置。修改后重新部署生效。Gate 未配置时 fail closed 返回 503，不会调用上游。

验证成功设置 `HttpOnly; Secure; SameSite=Strict; Path=/api; Max-Age=86400` cookie。会话含过期时间、随机 nonce 与 HMAC 签名；使用试用码作为服务端签名密钥。旋转试用码使旧会话失效。没有用户数据库、账号或单人撤销。

API 强制 POST、JSON、同源 Origin、有效会话。客户端 body 只可包含 messages，不能覆盖 endpoint/model/key。上游 redirect 禁止，固定 HTTPS。仅返回模型 content，不返回上游 envelope、headers、诊断或 secrets。业务代码没有正文/Authorization 日志。

## 轻量保护

- messages 最多 6 条，总计 100,000 UTF-16 字符（包含指令、资料与修复上下文）；超限提示拆分。
- 输出最多 6,000 tokens，返回内容最多 100,000 字符。
- 上游 120 秒 abort，函数 180 秒上限；超时与连接/响应解析异常分别显示脱敏错误；旧结果保留。
- 每实例每 IP 每分钟登录 5 次、AI 8 次，每实例总 AI 每分钟 60 次。
- IP 仅以服务端 HMAC 摘要放在短期内存桶，不写日志。

重要限制：内存频控不跨实例共享、冷启动重置，不能当硬费用上限。5–10 人 Pilot 必须配合供应商硬预算/额度限制，必要时使用 Vercel Firewall 平台规则。邀请人需保密试用码；码泄露应立即旋转。客户端可修改 messages；该入口是受 Gate 保护、限长限输出的模型调用接口，不保证客户端提示词不可篡改。

## 部署、更新与回滚

1. 本机执行 `npx vercel login`，通过浏览器登录自己的账户，无需提供 Token 给助手。
2. 已创建项目并登录。后续先 `node scripts/prepare-pilot.mjs`，再 `npx vercel --cwd .pilot-deploy --yes` 生成 Preview。首次新机器可先 `npx vercel link` 关联现有 digest 项目。
3. Dashboard 填变量，并为模型供应商设置小额硬预算。需要让学生免 Vercel 登录时，检查 Deployment Protection 配置；保留应用 Pilot Gate。
4. 执行 `node scripts/prepare-pilot.mjs` 后 `npx vercel --cwd .pilot-deploy --prod`，记录实际 Production URL，完成上述公网 QA。保持同一个稳定域名，避免 IndexedDB 因域名变化看似丢失。
5. 更新前先跑 npm test/build/git diff --check，再用同一项目发布；不要另建域名当“更新”。
6. 回滚优先在 Vercel Deployments 中将前一可用 Pilot 部署提升为 Production；保留域名与环境变量。Core tag 是代码安全点，不含 Proxy，若回滚纯 Core 会失去 Pilot AI。回滚不删除浏览器 IndexedDB；不要让学生清空浏览器数据。
