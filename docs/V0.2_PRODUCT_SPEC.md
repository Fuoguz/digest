# Digest v0.2 Product Spec

状态：产品方向已批准；本文已按 2026-09-07 决策收缩范围。

## 1. 产品目标

Digest 是面向高校学生的 AI 研读与复习工作台，将课程资料、论文、案例和政策文本转化为可追溯、可复习、可关联的长期知识资产。

v0.2 Core 只围绕三个价值：AI 判断可回到原文；知识进入主动回忆；经用户确认的知识点形成真实语义关系。完成产品闭环优先于企业级架构、云能力和大规模性能。

## 2. 当前审计结论

- 真正可用：文本输入、基础 Markdown 转换、浏览器直连模型、四字段结果展示、简化本地节点、搜索标签、固定日期复习、D3 布局和导出链路。
- Demo：图谱按创建顺序和同 group 连线；“完成复习”没有 Recall/Reveal；关键词覆盖被称作 confidence；保存节点不含原文、完整结果或题目。
- Legacy：根 `app.js` 已不被入口加载；`style.css` 两套主题互相覆盖；旧 `digest_nodes` 与新 store 没有可靠迁移。
- UX 最大问题：官网、答辩信息和工具混在一条长页，回访用户无法直接进入资料和今日任务。
- 视觉最大问题：暗色渐变、半透明面板、发光和卡片嵌套抢占阅读空间。
- 图谱没有真实语义；Review 没有 Active Recall 闭环；AI 输出没有 Evidence Anchors。
- 浏览器 localStorage Key 只适合 Developer Mode。Production Proxy 是后续独立工作，不阻塞 v0.2 Core。

## 3. v0.2 Core 信息架构

- `/`：Digest Landing。深墨/深靛 Hero、克制节点动态、大留白和强排版。
- `/app`：Dashboard。今日待复习、已完成、连续学习天数、最近资料和快速导入。
- `/app/library`：资料列表、搜索、标签/来源/模式筛选、收藏、最近研读、待复习。
- `/app/reader/:id`：左原文、右 AI 研读；四种模式和 Evidence 定位。
- `/app/review`：Question → Recall → Reveal → Again/Hard/Good/Easy。
- `/app/graph`：只显示确认后的 KnowledgeUnit 与 Relation。
- `/app/search`、`/app/settings`：基础入口；生产级全库性能和服务端配置后置。

App 使用 Sidebar + Workspace；Reader 的右栏就是研读上下文，不再叠加第四栏。桌面优先，768 以下使用抽屉/分段视图。

## 4. Document 与 Library

Document：`id, title, sourceType, sourceUrl, rawContent, paragraphs, metadata, createdAt, updatedAt, tags, readingMode, digestResultId, evidenceAnchorIds, reviewState, relationIds, favorite, status`。ReadingResult、EvidenceAnchor、ReviewCard、KnowledgeUnit 与 Relation 独立存储，通过 ID 关联。

sourceType：text / markdown / pdf / legacy。readingMode：general / academic_paper / legal_case / policy_document。两者分别筛选。

导入支持：

- 直接粘贴文本；
- 拖拽或选择 TXT、Markdown；
- 浏览器端解析带文本层 PDF；保存文件名、文件类型、大小、页数、提取正文和段落；
- 扫描 PDF 无文本时显示：“当前 PDF 未检测到可提取文本，请使用文本版 PDF 或粘贴正文。”

不实现 OCR、Word、PPT。导入成功后进入 Library，并可继续进入 Reader → Analyze → Evidence → Review。M1+M2 只完成资料入库和页面入口，Reader 细节从 M3 开始。

## 5. Reading Modes 与 Evidence

- General：summary、mainPoints、arguments、framework、reviewQuestions。
- Academic Paper：researchQuestion、method、findings、evidence、limitations、reusableInsights、reviewQuestions。
- Legal Case：facts、legalIssues、rules、arguments、reasoning、holding、reviewQuestions。
- Policy Document：background、targetAudience、objectives、measures、responsibleActors、timeline、implications、reviewQuestions。

模型输出必须经 schema validation。重要 Claim 引用 EvidenceAnchor：`sourceParagraph, quote, startOffset, paragraphIndex, confidence`。confidence 在 v0.2 保留为 nullable 字段，不展示模型自评百分比。

程序必须确认 quote 精确存在于保存的原文快照，再生成 offset。失败显示“暂无可靠原文依据”。引文匹配只证明定位存在，不证明 AI 推论正确。质量区改为 Output Completeness / Grounding Check。

## 6. Active Recall

每道 Review Card 独立保存问题、答案、依据、历史和 nextReviewAt。答案在 Reveal 前不进入可访问 DOM。

- Again：首次/重置 1 天；
- Hard：首次 3 天，后续适度延长；
- Good：首次 7 天，后续约 2 倍；
- Easy：首次 14 天，后续约 2.5 倍。

使用 simple-v1 adapter，为未来 FSRS 留接口，本版不实现 FSRS。Dashboard 指标从真实导入、研读和评分事件计算，不增加积分。

## 7. KnowledgeUnit 与 Semantic Graph

Document 是资料容器，不等价于图谱节点。

KnowledgeUnit：`id, documentId, claimId, label, summary, type, evidenceIds, tags, createdAt, status`。AI 可从重要 Claims 建议 3–8 个；用户点击“沉淀为知识点”后 status=confirmed，才进入正式图谱。

Relation：`sourceKnowledgeUnitId, targetKnowledgeUnitId, type, reason, evidenceIds, status`。type 为 related_to / supports / contradicts / example_of / prerequisite_of / causes。AI 生成 suggested，用户确认后进入正式图谱；允许无关系和孤立节点。

Core Graph 必须完成：从两份资料产生知识点、AI 建议关系、确认、D3 显示类型和 reason、节点回到来源 Reader/Evidence、无关知识不连边。严禁按创建顺序、标签或 group 强行连边。

## 8. 视觉系统

Landing：深墨 `#09111F`、深靛 `#111D38`、暖白文字；品牌动态只表达节点聚合，克制且支持 reduced-motion。

App：warm white `#F7F6F2`、surface `#FFFFFF`、ink `#181816`、secondary `#6F6D67`、border `#E5E2DA`、cobalt `#3157D5`。Evidence 使用暖黄 `#F4C95D` / `#FFF1B8`，作为 Digest signature interaction。

间距 4/8/12/16/24/32/48/64；圆角 6/10/14；动效 150–250ms，只用于状态和空间关系。避免玻璃拟态、蓝紫渐变、glow、卡片套卡片和装饰性图标。

支持 1440、1280、1024、768、390；M7 完整 polish，M1+M2 先保证 1440 和 390 的 Landing、Dashboard、Library、Import 可用。

## 9. 简化旧数据迁移

首次启动读取 `digest_nodes` 与 `digest:state:v1`。若存在旧数据，生成可下载 JSON backup；尽可能迁移 title / insight / tags / createdAt。缺原文统一标记 legacy_incomplete，不生成题目、Evidence 或关系。保留旧 key，不主动删除；迁移失败不写完成标记，允许重试。

不建设 BroadcastChannel、复杂 revision conflict、migrationIssues 管理 UI、checksum 恢复、多源同 ID 冲突框架或企业级恢复系统。解析失败时保留旧 key，并向用户显示可重试状态。

## 10. 本轮明确不做

Production authentication、quota、CSRF、API idempotency、多用户、云同步、Web Worker 千文档搜索、1000 文档 benchmark、FSRS、OCR、Word/PPT、Cloudflare adapter、复杂多标签并发、完整 soft-delete、企业级迁移恢复。

Production API Proxy 单独设计和交付，不作为 Core 阻塞项。

## 11. 里程碑

M1 Landing/App 分离与 Dashboard；M2 IndexedDB/Library/Text-Markdown-PDF Import；M3 Reader 与四模式；M4 Evidence；M5 Active Recall；M6 KnowledgeUnit/Semantic Graph；M7 polish/responsive/states；M8 tests/legacy cleanup/docs。

本轮只实施 M1+M2，完成后停止等待 review。
