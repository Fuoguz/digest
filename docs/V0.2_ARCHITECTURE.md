# Digest 0.2.1 架构与 AI 工作流

更新：2026-09-18。本文描述当前工作树；历史 v0.2 Core 结论见原阶段发布报告。

## 入口与路由

沿用 Vanilla JavaScript + ES Modules、轻量 History Router、IndexedDB、Node 静态开发服务及 Vercel Functions。无需 React/Next.js 或数据库服务。

- `/`：Landing，先作答、核查依据、修订理解。
- `/app/`：继续学习，最近课程/任务/Attempt/材料。
- `/app/courses` 与 `/app/courses/:id`：课程列表、材料关联、任务、最近作答。
- `/app/tasks/:id?attempt=:id`：历史首次答案、反馈、Evidence、修订；`attempt=new` 独立重答。
- `/app/library`、`/app/reader/:id`、`/app/review`、`/app/graph`、`/app/search`、`/app/settings`：既有能力保留。

训练领域及数据事务在 `domain/training.js`、`data/training-repository.js`；UI 为 `workspace/training.js`。原 Reader / Evidence / Review / Graph 领域继续复用。

## 数据模型与升级

数据库名称不变：`digest-v02`。物理版本 **2**；onupgradeneeded 只补建不存在的 stores，不清库或重写旧记录。升级被旧标签阻塞时提示关闭其他标签；versionchange 关闭旧连接。

旧 stores 保持：documents、readingResults、evidenceAnchors、reviewCards、knowledgeUnits、relations、activities、settings。

新增：

| Store | 主要字段 |
| --- | --- |
| courses | id, title, description, createdAt, updatedAt, documentIds, taskIds |
| tasks | id, courseId, title, prompt, rubric, description, documentIds, createdAt, updatedAt, version, draftAnswer |
| attempts | id, taskId, courseId, userAnswer, submittedAt, taskSnapshot, feedbackId, status, activeRequestId, revision[] |
| feedback | id, attemptId, overall/summary, strengths[], gaps[], evidenceRefs, suggestedNextStep, sourceRevisions[], modelInfo.version/transport/model, createdAt |

Revision：id、userAnswer、reflection、createdAt、feedbackId、verification=unverified；追加在原 Attempt 中，原 userAnswer 永不覆盖。status 为 submitted → reviewed → completed，仅表示流程状态，不表示掌握程度。

Task snapshot 保留当时问题、rubric、版本与材料 ID。已提交 Attempt 在 AI 前原子保存。每个反馈有独立 ID，成功前保留旧反馈指针。commit 在单个事务核对 activeRequestId、Task version、Document sourceSignature，并接收 AbortSignal；取消/旧响应/材料变化不能覆盖结果。刷新后未完成请求显示可重试，不依赖旧 in-memory controller。

课程删除只级联其 tasks/attempts/feedback；Library 文档、ReadingResult、旧 Review/Knowledge/Relation 不动。Evidence anchors 保留，避免破坏其他历史引用。正在被任务引用的材料不能直接移出课程，需先调整任务。

## Feedback 工作流

1. **确定输入**：固定 Task snapshot、rubric、课程名称/说明和学生答案；按句分割 answerChecks（确定性候选句，并非声称已理解语义）。
2. **限定材料**：只取 Task 明确选择的课程文档；生成现有 SHA-256 sourceRevision 与段落快照。小规模完整上下文，不做 embeddings 或隐蔽截断。材料总量上限 60,000 UTF-16 字符，答案 16,000；序列化消息总量超过 95,000 时拒绝。
3. **模型反馈**：一次 structured JSON 请求，要求核查候选句、评价标准与材料，返回 overall、strengths、gaps、suggestedNextStep。条目含 type、userAnswerQuote|null、explanation、support、evidenceCandidates、suggestedAction。无标准时不冒称教师评分。
4. **结构校验**：必填字段、类型、条数、长度、support 枚举；白名单提取，不直接渲染模型 HTML。反馈不自动 repair，以明确失败/手动重试限制成本。原 Reader 最多一次 repair 保留。
5. **Evidence validation**：答案引用必须是学生原句；课程引文须在指定文档指定段落精确唯一出现。程序生成 offsets，忽略模型伪造状态/位置。无 valid anchor 的条目标记 no_evidence，无定位链接。
6. **原子保存与展示**：反馈、anchors、Attempt 指针、metadata 事件一次提交。展示“模型语义判断”与“引用定位验证”的区别，不给百分比。源版本变化时保留历史反馈但停用旧依据。
7. **修订**：保存不同于上次答案的文本和修改说明；未自动检查修订质量，明确尚未验证。可创建不同案例的新 Task 或独立重答同题。

这是可分步检查的代码流水线，不是多 Agent 系统。当前材料都放入有界上下文，不承诺自动识别全部需要核查的隐含判断，也不承诺长课程检索召回率。

## 生产 AI 路径

Browser → `/api/access` 试用码认证 → `/api/digest`（研读及反馈）或 `/api/relations` → 固定服务端 HTTPS 模型地址。

四个服务器变量：MODEL_API_KEY、MODEL_API_BASE_URL、MODEL_NAME、PILOT_ACCESS_CODE。客户端只传 messages；不指定服务器 key/endpoint/model。HttpOnly/Secure/SameSite cookie、同源 Origin 检查、输入上限、实例内频控、脱敏错误保留。供应商硬预算仍需运营设置，实例频控不是全局费用上限。

当前 server deadline **165 秒**，客户端 Proxy deadline **175 秒**，Vercel function maxDuration **180 秒**。输出上限 **12,000 tokens / 100,000 字符**。网络异常最多一次重试；400/422 可回退一次不带 response_format。总调用仍受同一个 server deadline 限制。浏览器取消不保证供应商立即停止计费，但本地结果不会被迟到响应覆盖。

Provider 使用 json_object（兼容性回退可不带），严格性由运行时 schema 强制；不是声称所有供应商都支持 JSON Schema constrained decoding。modelInfo 记录 prompt/workflow version 与 transport；生产真实模型名由服务器配置，客户端当前不记录具体供应商模型 ID。

## 原文与恢复

沿用 exact quote + paragraph + UTF-16 offsets + sourceRevision。matched 仅表示存在且定位唯一；不证明 claim 与 evidence 的语义关系。ambiguous/invalid/stale 不生成假跳转。

Feedback 链接可在未生成 ReadingResult 时直接打开 Reader anchor；手机有返回反馈按钮。返回恢复选中反馈条目与阅读上下文；编辑中的修订草稿保存至 settings。源页面路由受内部路径白名单限制。

Backup format 保持 digest-v02，version 升至 **2**，新增四表。兼容旧 version 1。先完整校验结构、外键、日期，重新校验来源和答案引文，再在空学习库一个事务导入；失败无部分写入。清除导入的 activeRequestId，不信任传入 matched 状态。settings/Key 不进入备份，未提交修订草稿也不在备份中。

**回滚注意**：升级过的浏览器不可直接用仅打开 DB version 1 的旧构建运行。回滚应用需保留 version 2 的兼容打开逻辑和新增 stores；不得以清库作为回滚。

## 本地事件与 Activation

记录 document_imported、reading_started/completed、evidence_opened、course_created、task_opened、attempt_started/submitted、feedback_generated、feedback_evidence_opened、revision_saved、task_completed、review_started/completed。旧 review_rated 为兼容排期统计保留。

活动只有标识符、类型、时间和 activationCandidate；不记录正文、答案或 rubric，不上传外部 analytics。task_completed 只在首次保存有变化的修订及修改说明时记录，代表候选激活。有效修正与学习效果由真实 Pilot 人工核查。

## 测试与边界

Node tests 覆盖旧能力及新增事务/schema/race/restore；真实 Chrome 使用隔离 origin 和 mock fixture 完成 UI 与文件备份往返。mock 不证明真实模型可靠性。

无云同步、全局配额、自动新题、语义正确性验证、复杂检索或长期保留率测量。真实模型与公网状态见 NEXT_RELEASE_REPORT.md。

## 2026-09-24 UI 与长文更新（覆盖上文旧上下文上限）

入口、技术栈、IndexedDB v2 和备份格式保持不变，无新增数据库表、无数据清理。新增 src/domain/context.js 提供保留 paragraphIndex/segmentStart 的原文分段、精确片段及 lexical-v1 检索。

Reader：选定全文/段落范围 → <=10k 字符分段 → 每段 schema 校验与原文 Evidence 校验 → 原子受保护 checkpoint → 整体概览（仅引用已有 claim IDs）→ 原子提交完整结果并清除 checkpoint。每次至多12段。checkpoints 放 settings，key 含源版本/范围/语言/workflow版本；旧 requestId 和取消响应不能覆盖新进度。任何分段或综合失败保留旧正式结果。单段无需额外综合调用。

模型优先返回 quoteId，程序仅从本次提供的 evidenceExcerpts 中取回精确子串；依旧用完整文档快照验证唯一匹配、offset、sourceRevision。跨窗口片段 ID 包含原段内 offset，避免编号冲突。兼容旧 quote 输出，不对错误 quote 做模糊修复。定位正确与语义判断正确仍分开。

Feedback workflow course-feedback-v2：对限定的课程材料做词语检索（最多24k字符），保留全部源快照用于验证。替代过去60k材料直接拒绝；不声称检查未入选文本。答案仍最多16k，序列化上下文超过95k时明确拒绝。返回新增 retrievalScope、outputLanguage；旧字段与旧反馈兼容。跨语言问题与原文词语不重合时检索可能漏证据，不是 embeddings 或完整RAG。

ReadingResult 新增 scope、outputLanguage、overview；已有字段保留。settings 中未提交草稿和研读checkpoint不进入备份，已提交结果继续正常备份。feedback_rated 活动只含反馈ID与枚举，不包含答案/材料。

本地化由静态字符串目录实现，只翻译作者编写的界面字符串；用户标题、正文、历史AI内容不经过DOM全局替换。切换语言前等待草稿持久化，sessionStorage临时恢复当前表单/展开状态，刷新后恢复。AI语言独立传入请求，不自动改写历史结果。正式UI与模型文本仍通过 textContent / 安全转义渲染。

UI 新增 upgrade.css，共享字体、间距、分隔线、状态与响应式规则。沿用暖白、墨黑、钴蓝与琥珀依据；无需图像装饰或框架更换。
