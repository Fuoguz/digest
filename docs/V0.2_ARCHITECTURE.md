# Digest v0.2 Core Architecture

## 决策

Vanilla JavaScript + ES Modules，两个 HTML 入口与轻量 History Router。无需 React/Next.js 或后端重构。IndexedDB 数据库名 digest-v02，物理版本仍为 1：M1 已预建当前所需 stores，因此本轮不升库版本、不清库。

## 数据

Stores：documents、readingResults、evidenceAnchors、reviewCards、knowledgeUnits、relations、activities、settings。

- Document：id/title/sourceType/sourceUrl/rawContent/paragraphs/metadata/createdAt/updatedAt/tags/readingMode/digestResultId/evidenceAnchorIds/favorite/status。旧 reviewState/relationIds 兼容保留，Dashboard 不依赖它们计算。
- ReadingResult：documentId/sourceRevision/requestId/readingMode/sections/reviewQuestions/createdAt。Claim 为 id/text/kind/evidenceIds，可选 knowledgeLabel。题目含 question/answer，可选 claimIds；旧数据没有新增字段仍可读取，但不补造直接 Evidence。
- EvidenceAnchor：id/documentId/sourceRevision/paragraphIndex/pageNumber/quote/startOffset/endOffset/paragraphStartOffset/paragraphEndOffset/validationStatus。
- ReviewCard：documentId/readingResultId/sourceRevision/sourceSignature/question/answer/questionKey/claimIds/evidenceIds/status/nextReviewAt/intervalDays/scheduler/history/version/createdAt。
- KnowledgeUnit：documentId/readingResultId/claimId/label/summary/type/evidenceIds/tags/sourceRevision/sourceSignature/status/version/createdAt。
- Relation：sourceKnowledgeUnitId/targetKnowledgeUnitId/type/reason/evidenceIds/status/createdAt，status=suggested/confirmed/rejected。
- Activity：真实导入、研读完成、知识沉淀与复习评级事件。按本地日期统计。

## Grounded AI

Document Snapshot（正文、模式、段落）→ DeveloperTransport（兼容 Chat Completions）→ 单次 analyze → schema validation → 最多一次 repair → 程序校验 Evidence → 原子保存。没有 Agent loop。API Key 仅在用户配置的 Developer Mode 使用，备份不包含设置或 Key。

sourceRevision 是正文、模式、段落签名的 SHA-256。保存检查 documentId、签名与 requestId；取消或旧响应无法覆盖当前结果。新结果成功前保留旧结果。历史 Reading Result 与 anchors 保留，复习/知识来源可带 result/evidence/claim 参数重新打开。

Evidence：段落存在、quote 非空、对应段落精确唯一出现，并核对全局切片，才能 matched。重复为 ambiguous，缺失为 invalid，版本不同为 stale。忽略模型提供的状态/offset；无模糊匹配。offset 使用 UTF-16，与 String.slice/DOM 一致。页码只取本地可靠 metadata。原文和模型文本通过 textContent/text node 渲染，高亮分割文本节点。

## 学习事务

LearningRepository.atomic 在单一 readwrite 事务中读取和写入所需 stores，成功提交才反馈成功。添加题目按 documentId + normalized question 去重；评级核对版本、到期、活动状态及 source signature，原子保存历史/排期/Activity。算法标记 simple-v1，可日后替换；间隔初始 1/3/7/14，后续 Hard 1.2x、Good 2x、Easy 2.5x，Again 1 日，上限 365 日。

KnowledgeUnit 仅用户确认保存，校验当前来源与研读版本。关系请求最多 40 个当前筛选的有效知识点，包含通过验证的来源片段。结构/端点/类型/理由校验并去重；请求期间版本变化拒绝保存。模型 status 无效，始终 suggested。正式图谱仅 confirmed 且来源未失效的节点与关系。

当前为小规模本地产品，事务 getAll、搜索线性扫描、D3 有限迭代静态布局；没有千节点性能承诺或复杂多标签冲突框架。

## 备份与迁移

旧 localStorage 自动备份并保留 key；尽可能迁移 title/insight/tags/date，缺原文 legacy_incomplete。不补造研读、题目、依据。失败下次重试。

v0.2 exportBackup 一致读取学习 stores；restoreBackup 校验结构/引用/日期，在空学习库原子恢复，重新计算 Evidence，不信任导入 matched 状态。拒绝非空库导入与超过 50 MB 文件，无覆盖合并。原 PDF 文件不保存，正文及 metadata 会备份。

## 验证与部署边界

node:test + fake-indexeddb，全部离线；mock 服务与存储故障注入仅 tests/fixtures，不进入 dist。build 复制实际入口、本地资源及运行模块。server 仅允许产品目录，拒绝目录穿越/隐藏路径，绑定 loopback。

Production Proxy、鉴权、配额、云同步是后续独立方案；当前运行没有这些能力。真实模型验收状态见 V0.2_REAL_MODEL_ACCEPTANCE.md。
