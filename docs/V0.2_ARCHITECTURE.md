# Digest v0.2 Architecture

状态：已按批准范围收缩；目标是快速交付可用 Core，而非架构示范。

## 1. 核心决策

1. Vanilla JavaScript + ES Modules，不迁 React/Next.js。
2. `/` 和 `/app` 使用两个 HTML 入口；轻量 History Router 管理 App 页面。
3. IndexedDB 保存 Document、ReadingResult、ReviewCard、KnowledgeUnit、Relation 和 Activity；localStorage 只保留 Developer Mode Key、轻量偏好和旧数据。
4. 页面组件使用 `render(container, state)` 与事件委托；领域计算保持无 DOM 依赖。
5. PDF 使用 pdfjs-dist 在浏览器解析文本层；worker 资源随项目构建，不调用远程 CDN，不做 OCR。
6. Production Proxy 延后；Developer Mode transport 继续可用，但不进入 M1/M2。

## 2. 目录边界

```text
index.html                      Landing
app/index.html                  Workspace shell
src/landing.js                  Landing interaction
src/workspace/main.js           App bootstrap、轻量路由、事件协调
src/workspace/views.js          Dashboard、Library、占位页和 shell 视图
src/domain/documents.js         Document normalization 与筛选
src/data/db.js                  IndexedDB repository
src/data/legacy-migration.js    一次性旧数据备份迁移
src/importers/                  text/markdown、pdf
src/styles/                     tokens, landing, app
vendor/pdfjs/                   build-copied pdf.js runtime
```

M3 后增加 reader/AI；M4 增加 evidence；M5 review；M6 knowledge-units/graph。现有 `src/modules/**` 暂留供旧入口历史对照，M8 在新链路通过后清理。

## 3. IndexedDB v2

数据库 `digest-v02`，stores：documents、readingResults、evidenceAnchors、reviewCards、knowledgeUnits、relations、activities、settings。M1/M2 repository API：`openDatabase, listDocuments, getDocument, saveDocument, removeDocument, listActivities, addActivity, runLegacyMigration`。写入 Promise resolve 后才显示成功。

## 4. Document model

```text
{ id, title, sourceType, sourceUrl, rawContent,
  paragraphs: [{ id, paragraphIndex, text, startOffset, endOffset }],
  metadata: { originalFileName, mimeType, fileSize, pageCount, importedAt },
  createdAt, updatedAt, tags, readingMode,
  digestResultId: null, evidenceAnchorIds: [],
  reviewState: { dueCount: 0, lastReviewedAt: null, nextReviewAt: null },
  relationIds: [], favorite, status: ready | legacy_incomplete }
```

paragraph offsets 基于 rawContent 的 JavaScript UTF-16 `[startOffset,endOffset)`。规范化 CRLF→LF，空行切段；Markdown 导入时去除常见标记并保存可读正文。PDF 每页提取文字，页间保留段落边界；metadata 保存原始文件名、大小和页数。

## 5. PDF import

ImportDialog 接受 PDF/TXT/Markdown，也支持 drag & drop。单文件最大 20 MiB；M2 每次一个文件。

PDF：ArrayBuffer → pdfjs `getDocument` → 每页 `getTextContent` → 按文本项坐标组成行/段 → Document。解析全在浏览器完成，原始二进制不持久化。文本少于 20 个非空白字符时显示批准文案。加密、损坏和超大文件显示可恢复错误。

## 6. 简化 legacy migration

首次打开读取两个旧 key，存在则在 localStorage 与 IndexedDB settings 中创建可下载 JSON backup；提取 title/label、insight、tags、createdAt。迁移项使用稳定 `legacy-<id>`，sourceType=legacy、status=legacy_incomplete，rawContent 保持为空，不生成题目、Evidence、KnowledgeUnit 或 Relation。成功后 settings 标记完成；旧 key 保留。失败记录原因但不会标记完成，下次启动自动重试。

不实现 checksum、竞争锁、复杂冲突 UI或恢复框架。浏览器无法无交互静默下载文件，因此 Dashboard 提供备份下载动作。

## 7. 后续模型

ReadingResult 按 readingMode 使用严格 schema。Claim：`id,text,kind,evidenceIds`。EvidenceAnchor 精确匹配原文后才保存 matched；confidence=null。ReviewCard 独立按题调度。KnowledgeUnit 从 Claim 建议，用户确认才进入图谱。Relation 连接 KnowledgeUnit，suggested 经确认才入图。

这些 store 在 M2 建立，UI 与逻辑在 M3–M6 实现。

## 8. 路由、构建与测试

server.js 对 `/app` 和 `/app/*` 返回 app/index.html；真实资源不存在返回 404。`npm run build` 复制两个入口、src、样式和固定版本 pdfjs 到 dist；生产只发布 dist。

M1/M2 测试 Document paragraph/offset、TXT/Markdown、PDF text/no-text、IndexedDB CRUD、简化迁移、App route/build。npm test 离线运行，不要求真实 Key。
